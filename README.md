# AgentCrew — 多智能体工作方案制定系统

面向科研与课题工作的 **多 Agent 协作平台**。描述你的研究需求，由多个专业角色分工协作，自动完成课题规划、文献调研、实验设计、预算编制与方案终审，并在关键节点等待你审核把关。

适合：文献综述撰写、实验方案设计、完整科研工作方案制定。

---

## 核心特点

- **多角色协作** — 课题规划师、文献专家、实验设计师、预算分析师、终审专家分工配合，可按场景自由勾选参与角色
- **三种协作模式** — 串行模式按流程依次执行；辩论模式通过正反方多轮答辩完善方案；投票模式由多个求解者并行生成后聚合选出最优
- **三种工作场景** — 文献综述、实验方案设计、完整工作方案，按需选择流程深度
- **工作流模板** — 推荐模板与自定义模板，支持 `{{变量名}}` 占位符快速复用配置
- **人机协同** — 预算审批、方案终审等关键步骤自动暂停，你可审核输出、提出修改意见后再继续或终止
- **实时可见** — 工作流页面流式展示各 Agent 的输出与工具调用进度，运行中可中止、从中断处继续
- **参考文件支持** — 上传 txt / md / csv / json 作为背景资料，供规划与文献 Agent 参考（单文件最大 2MB）
- **历史方案管理** — 每次生成的方案自动命名标题，支持按标题或需求搜索，随时回看详情
- **多版本方案** — 同一课题可多次生成方案，自动归组并编号；支持并排对比差异、标注优劣点，可标记「当前最佳版本」
- **一键导出** — 方案可导出为 Markdown、Word（`.docx`）或 LaTeX（`.tex`）
- **自定义 Agent** — 除内置角色外，可创建、编辑专属 Agent（含工具绑定与推理模式）
- **学科领域审稿** — 内置计算机、生物学、材料化学等领域审稿专家，可按需加入工作流
- **多用户隔离** — 注册登录后，历史方案与自定义 Agent 按用户独立存储
- **应用内帮助** — 侧边栏「使用帮助」提供完整操作指南，无需查阅文档即可上手

## 快速开始

### 1. 准备环境

```bash
git clone <your-repo-url>
cd AgentCrew

cp .env.example .env
```

编辑 `.env`，**至少填写**：

| 变量 | 说明 |
|------|------|
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥（[获取地址](https://platform.deepseek.com/)） |
| `JWT_SECRET` | 登录令牌密钥，**生产环境务必修改为随机字符串** |

可选：`SEMANTIC_SCHOLAR_API_KEY` 可提高文献检索速率；`ADMIN_PASSWORD` 可修改默认管理员密码。

### 2. 安装并启动

```bash
# 安装后端依赖
pip install -r requirements.txt

# 安装前端依赖
cd frontend && npm install && cd ..

# 终端 1：启动后端（http://localhost:8000）
python run.py

# 终端 2：启动前端（http://localhost:3000）
cd frontend && npm run dev
```

浏览器访问 **http://localhost:3000** 即可使用。

### 3. 登录

首次启动会自动创建管理员账号：

| 用户名 | 密码 |
|--------|------|
| `admin` | `.env` 中的 `ADMIN_PASSWORD`（默认 `admin123`） |

也可在登录页注册新账号。每个用户的数据相互独立。

### 4. 生产部署（可选）

构建前端后，只需启动后端即可同时提供 Web 界面：

```bash
cd frontend && npm run build && cd ..
python run.py
```

部署前请修改 `JWT_SECRET` 与 `ADMIN_PASSWORD`。

### 5. 容器化部署（Docker）

推荐使用 Docker 一键部署，镜像内已包含构建好的前端，单容器即可对外提供服务。

#### 前置要求

- 已安装 [Docker](https://docs.docker.com/get-docker/)（Docker Desktop 或 Docker Engine）
- 已安装 [Docker Compose](https://docs.docker.com/compose/install/)（Docker Desktop 已内置）

#### 部署步骤

```bash
# 1. 克隆项目
git clone <your-repo-url>
cd AgentCrew

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，至少填写 DEEPSEEK_API_KEY，并修改 JWT_SECRET、ADMIN_PASSWORD

# 3. 构建并启动（后台运行）
docker compose up -d --build

# 4. 查看启动日志（可选）
docker compose logs -f
```

浏览器访问 **http://localhost:8000** 即可使用（端口可在 `.env` 中通过 `APP_PORT` 修改）。

首次启动会自动创建管理员账号（用户名 `admin`，密码为 `.env` 中的 `ADMIN_PASSWORD`）。

#### 数据持久化

容器内的 SQLite 数据库、上传文件与历史方案保存在 `./data` 目录，已通过 Docker 卷挂载到宿主机：

```
./data/
├── app.db          # 用户与方案数据库
├── results/        # 历史方案 JSON
└── uploads/        # 用户上传的参考文件
```

**请定期备份 `data/` 目录**，删除该目录将导致数据丢失。

#### 常用运维命令

```bash
# 停止服务
docker compose down

# 重新构建并启动（代码或依赖更新后）
docker compose up -d --build

# 查看容器状态
docker compose ps

# 查看实时日志
docker compose logs -f agentcrew
```

#### 生产环境建议

| 项目 | 说明 |
|------|------|
| 密钥安全 | 务必修改 `JWT_SECRET`、`ADMIN_PASSWORD`，勿将 `.env` 提交到版本库 |
| 反向代理 | 建议在容器前加 Nginx / Caddy，配置 HTTPS 与 WebSocket 转发（路径 `/ws`） |
| 端口映射 | 默认映射 `8000:8000`；修改 `.env` 中 `APP_PORT` 可更改宿主机端口 |
| 资源限制 | 多 Agent 工作流会调用 LLM API，建议在 `docker-compose.yml` 中按需设置 `mem_limit` |

#### 仅使用 Docker（不用 Compose）

```bash
docker build -t agentcrew .
docker run -d \
  --name agentcrew \
  -p 8000:8000 \
  --env-file .env \
  -v "$(pwd)/data:/app/data" \
  --restart unless-stopped \
  agentcrew
```

Windows PowerShell 下挂载卷可写为：`-v ${PWD}/data:/app/data`

## 使用指南

> 应用内可通过侧边栏 **使用帮助** 查看完整操作说明。

### 创建一份工作方案

1. 登录后进入 **工作台**
2. （可选）从 **推荐模板** 或 **我的模板** 快速开始，填写模板参数
3. 选择 **协作模式**（串行 / 辩论 / 投票）
4. 选择场景类型（文献综述 / 实验方案 / 完整方案）
5. 勾选本次需要参与协作的 Agent 角色（串行模式下可自由勾选；取消某角色将跳过其对应任务）
6. 在文本框中详细描述研究课题：背景、目标、约束条件等
7. （可选）上传参考文件，补充课题背景或已有资料
8. 点击 **启动多智能体工作流**，进入工作流页面实时查看进度

### 协作模式说明

| 模式 | 说明 |
|------|------|
| **串行模式** | 按固定流程依次执行，可自由勾选参与角色 |
| **辩论模式** | 正反方多轮答辩，由裁判整合完善方案 |
| **投票模式** | 多个求解者并行生成方案，聚合选出最优结果 |

### 工作流进行中

- 各 Agent 的输出会**逐段流式显示**，工具调用（文献检索、文件解析、计算等）状态同步展示
- 遇到需人工审核的节点，页面会出现**审核面板**：可填写修改意见，选择批准继续或驳回终止
- 运行中可随时 **中止**；之后可从断点 **继续** 执行
- 完成后可直接 **导出 Markdown、Word 或 LaTeX**

### 工作流模板

- 在工作台可将当前配置 **保存为模板**（场景、Agent、需求描述结构）
- 模板支持 `{{变量名}}` 占位符，使用时填写参数自动生成完整需求
- 历史方案页面也可 **保存为模板**，便于复用已有课题配置

### 管理 Agent 角色

进入 **Agent 角色** 页面，可以：

- 查看内置核心协作角色与学科领域审稿专家
- 新建自定义角色（名称、背景、目标、可用工具、是否启用推理模式）
- 编辑或删除自己创建的自定义角色

自定义角色创建后，可在工作台中与其他内置角色一起勾选使用。

### 查看历史方案

进入 **历史方案** 页面：

- 列表按**课题**分组展示，每个课题可包含多个方案版本
- 顶部**搜索框**支持按标题或需求描述检索
- 点击课题进入版本列表，可查看各版本详情、导出 Markdown / Word / LaTeX
- 勾选两个版本后点击 **对比所选版本**，并排查看各任务差异与优劣分析
- 点击 **设为最佳** 标记当前课题的最佳方案版本
- 点击 **再生成一版** 可基于同一课题快速启动新的工作流

> 相同场景与需求描述的方案会自动归入同一课题；版本号按生成顺序递增。也可从历史课题页一键再生成新版本。

## 三种场景说明

| 场景 | 适用情况 | 协作流程 |
|------|----------|----------|
| **文献综述生成** | 需要梳理领域文献、形成综述框架 | 课题规划 → 文献调研 → 方案终审 |
| **实验方案设计** | 已有方向，需设计实验方法与预算 | 课题规划 → 实验设计 → 预算编制 → 方案终审 |
| **完整工作方案** | 从零到完整方案的一站式制定 | 五个 Agent 全流程协作 |

## 内置 Agent 角色

| 角色 | 职责 |
|------|------|
| **课题规划师** | 分析需求，梳理研究框架与关键问题 |
| **文献调研专家** | 检索学术文献（Semantic Scholar / PubMed），整理综述要点 |
| **实验方案设计师** | 设计实验方法、对照组、样本量等（启用推理增强） |
| **预算资源分析师** | 估算人力、设备、试剂等资源与预算 |
| **方案终审专家** | 整合各阶段成果，做质量评审与最终定稿 |

此外还内置计算机、生物学、材料化学等 **学科领域审稿专家**，可在串行模式下额外勾选加入工作流。

## 常见问题

**Q：服务重启后进行中的工作流还在吗？**  
A：进行中的任务保存在内存中，重启后会丢失；**已完成的方案**会持久保存，可在历史方案中查看。

**Q：文献检索需要什么额外配置？**  
A：默认可用 Semantic Scholar 与 PubMed；配置 `SEMANTIC_SCHOLAR_API_KEY` 可提高检索速率。

**Q：支持哪些参考文件格式？**  
A：txt、md、csv、json，单文件不超过 2MB。

**Q：数据存在哪里？**  
A：默认在 `data/` 目录（数据库、上传文件、历史方案）。建议定期备份该目录。

**Q：API 文档在哪里？**  
A：后端启动后访问 http://localhost:8000/docs 查看 Swagger 交互文档（需登录令牌）。
